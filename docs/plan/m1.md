# M1 core types, event store, ledger, import

Spec: S0, S1, S1a, S3, S11, S13, S17, S19.5. Architecture: A2, A3, A9.1, A9.3. Plan: `docs/plan/legacy-migration.md` (category ids), `docs/plan/engine-semantics.md` section 1 (types).

**Goal:** money and calendar primitives, an event store with undo, the immutable ledger plus overlays, the default categories, and file import.

**Exit criteria:**
- A CSV can be imported (dry run, then apply) and undone and redone.
- The default categories are seeded with the stable ids from `legacy-migration.md`.
- All unit tests pass, including invariants 4, 11 and 13.

---

### [x] M1.1 `internal/money`
- `type Cents int64`, plus `Add`, `Sub`, `Neg`, `Abs`, `Min`, `Max` and `String()` (for debugging only, never for UI copy).
- `PerDay(left Cents, daysLeft int) (perDay, lastDayExtra Cents)`: floor division with the remainder going to the last day (S17). `daysLeft <= 0` is treated as 1.
- `Pct(base Cents, basisPoints int64) Cents` floors. `FromDecimalString(s string) (Cents, error)` parses provider strings such as `"-33293.43"` exactly, using `math/big` and never floats (port `cents()` from `git show main:server/simplefin.go`).
- Tests: `TestS17_PerDayRemainderToLastDay`, `TestA9_Inv10_PerDayTimesDaysPlusRemainder` (rapid), `TestMoney_FromDecimalStringExact` (including amounts with 3 decimal places and huge values).

### [x] M1.2 `internal/civil`
- `Date`, `YearMonth`, `ParseDate`, `AddDays`, `AddMonthsClamped` (the 31st clamps to month end), `DaysIn`, `DaysLeft(today Date) int` (includes today).
- `TxnTime{ Date *Date; Instant *time.Time }`. `MonthOf(t TxnTime, home *time.Location) YearMonth`: a date-only value is a calendar date and is **never** converted. A real instant converts to the home zone (S3).
- `HomeZoneAt(ym, changes []ZoneChange) *time.Location`: home zone changes are effective-dated, and past months keep their zone (S3).
- `NominalMonth(actual Date, nominal Date, intervalDays int) (YearMonth, attributed bool)`: S3 boundary attribution with tolerance `min(5, interval/4)` days, only for intervals of 28 days or more (A-010).
- Tests (`TestS3_*`): the 1st at midnight UTC stays on the 1st; an instant at 23:30 home time on the 31st stays in its month; DST spring-forward and fall-back days; boundary attribution inside and outside tolerance; a weekly item never attributed; zone change effective-dating.

### [ ] M1.3 event store (`internal/events`)
- `Append(ctx, tx, Event) (Event, error)`. An event carries kind, subject type and id, typed payload JSON, actor (`user`, `system`, `legacy-import`), `at`, and an optional idempotency key. A duplicate idempotency key returns the original event, not an error (A6).
- `Undo(ctx, tx, eventID)` appends an event with `reverses = eventID`. `Redo` reverses the undo. `Effective(ctx, q, filter)` returns the events still in force (not reversed an odd number of times), ordered by `(at, id)`.
- A payload registry maps each kind to a Go struct with a version, so old events still decode.
- Tests: `TestA9_Inv4_UndoRedoRestoresState` (rapid: random event sequences, undo a random one, redo it, compare the effective set), `TestEvents_IdempotencyKeyReturnsOriginal`.

Seed the S1a defaults with exactly the ids in `legacy-migration.md`. Subscriptions are their own internal bucket for the math (A-004) and are shown under spending in the UI.

- Tests: `TestS1a_DefaultsSeededWithStableIDs`, `TestS1a_EveryCategoryHasGroupAndBucket`.

### [ ] M1.5 transactions service (`internal/ledger`)
- `View(ctx, q, filter)` returns effective transactions: raw fields plus the overlay, the resolved month (override first, else S3 on `transacted_at` if present, else `posted`), the bucket from the category, and split parts.
- Overlay writes go through events (`overlay.set_category`, `overlay.set_note`, `overlay.hide`, `overlay.unhide`, `overlay.set_month`, `overlay.split`, `overlay.set_from_discretionary`). The overlay row is a projection rebuilt from events, and a projection rebuild test must pass.
- Hide (S11): sets `hidden`, writes a tombstone, and excludes the row from all math. Unhide reverses it.
- Splits (S19.6): parts must sum to the total. Each part has its own category, tags and note.
- Tests: `TestS11_OverlayNeverTouchesBankFields`, `TestS11_HiddenExcludedAndTombstoned`, `TestS19_6_SplitPartsSumToTotal`, `TestA9_Inv9_SplitCountsInOneBucketPerPart`, `TestLedger_ProjectionRebuildEqualsIncremental`.

### [ ] M1.6 categories service
- Create custom groups and categories: a category must be in a group, and a group in a bucket; groups cannot span buckets (S1a).
- Rename never changes the id. Delete requires a reassignment target, defaulting to "Other" in the same bucket. Merge moves transactions to the survivor (rules come in M6; leave a hook).
- Tests: `TestS1a_DeleteRequiresReassignment`, `TestS1a_MergeMovesTransactions`, `TestS1a_RenameKeepsID`.

### [ ] M1.7 import framework (`internal/importer`)
- Providers: `csv` (column mapping presets saved per institution), `ofx`/`qfx` (an in-repo SGML and XML `STMTTRN` parser), and `qif`. All go through normalization (a stub until M6).
- Flow: parse, **dry run** (rows that would be added, duplicates found by fingerprint, rows skipped and why), then apply as one batch. The batch is an event, and undoing it hides the batch's rows (it never deletes them).
- Dedupe against existing transactions by fingerprint and by provider id where the file provides one (S19.5).
- Tests: `TestS19_5_CSVDryRunWritesNothing`, `TestS19_5_ImportBatchUndo`, `TestA9_Inv11_ImportTwiceIdentical`, `TestS19_5_OFXSGMLAndXMLParse`, `TestS19_5_QIFParse`, plus fuzz tests for each parser (bank files are untrusted input).

### [ ] M1.8 manual accounts and transactions
- Provider `manual`: create an account (any kind) and add, edit or delete manual transactions through events (S11, S4 manual income).
- **Merge suggestion** (S11): when a synced transaction later arrives with the same amount within 3 days of a manual one, suggest merging them (the manual row's overlay is kept; the bank row becomes the raw side). Never merge on its own. This is also how "mark received" manual rows (S12a) resolve.
- Tests: `TestS11_ManualTransactionRoundTrip`, `TestS11_SyncedMatchSuggestsMergeNeverAuto`.
