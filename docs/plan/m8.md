# M8 PWA and cutover rehearsal

Spec: S16, S19.3 (push defaults), S19.7, S19.20, S0a (vocabulary). Architecture: A6, A9.7. Design: `docs/design-brief.md`. ADR-0003, ADR-0017. Plan: `docs/plan/legacy-migration.md`.

**Goal:** the PWA renders server snapshots only, works offline with a queue, and covers every core screen in the design brief. The legacy importer is finished and rehearsed.

**Exit criteria:**
- Playwright e2e passes for the main flows, including offline and reconnect, with axe checks clean.
- Review runs at swipe speed (a routine item takes under 3 seconds of interaction).
- The importer dry run on a copy of the owner's database is clean.
- **Owner gates:** visual review on a phone, then approval of the cutover.

The legacy UI already has strong pieces: the swipe card with flick momentum (`useSwipeCard`, with tests), sheets that flick to dismiss, motion and haptics, the bottom tab bar, phone layout fixes, the toast placed at the top on phones, the subscriptions page and calculators. **Reuse them**, but rewire them to the new API.

### [ ] M8.1 web structure and tokens
- Split `web/src/App.tsx` into `screens/` (home, review, uncategorized, cover, owed, money, bills, accounts, rules, activity, insights, settings, onboarding) and `components/` (the "components to design once" list in the design brief).
- Turn the existing CSS (`minimal.css`, `design-match.css`, `dashboard-refresh.css`, `features.css`, `buy.css`, `styles.css`) into one token file (light and dark) plus per-component CSS. Remove dead rules. Keep the current look; the palette and type direction are already approved.
- A router with real paths (or keep the hash, but one route per screen). The bottom tab bar stays on phones.

### [ ] M8.2 data layer (`web/src/data/`)
- Generate TypeScript types from `api/openapi.yaml` (openapi-typescript) and write a thin typed client.
- **IndexedDB cache:** `MonthState` snapshots with `engine_version` and `computed_at`, the review queue, accounts, and the outbox. The app opens instantly from cache and labels data with its age.
- **Outbox:** intents with idempotency keys. **Optimistic updates for review actions only** (confirm, recategorize). Every number updates only from server snapshots (ADR-0003).
- **Sync:** `GET /api/v1/sync/changes?cursor=` returns changed entities and fresh snapshots. On reconnect, push the outbox, then pull. Add server-sent events for the queue, snapshots and alerts (add `GET /api/v1/stream` server-side).
- **Conflicts:** last write wins per field; an explicit review decision beats a sync update (S16).
- **Delete** `web/src/model.ts` budget math and `applyAction`, `web/src/merchants.ts`, and the client-side demo (A-009). Remove their tests or move any still-relevant cases to the Go side.
- Tests: `TestS16_ReviewDecisionBeatsSyncUpdate` (Go), Playwright `offline-queue.spec.ts` (go offline, review 5 items, reconnect, assert the server state).

### [ ] M8.3 home (design brief screen 1)
- `GET /api/v1/home`: safe to spend total and per day, plus the quiet strip:
  - discretionary
  - "uncategorized" when non-zero
  - "owed to you" when non-zero
  - pending review held deposits
  - "after pending: $X" (S19.24)
- The next few things on the timeline, and **one** prompt at a time.
- States: normal, overspent, learning, stale ("data as of"), offline, partial. The cash check amber line (S10) is a placeholder until M9 computes it.
- Every number is tappable for its explanation (M3.6).

### [ ] M8.4 review (screen 2)
- A card stack with swipe right to confirm and left to recategorize, and a button for each gesture.
- The card shows: merchant, amount, date, account, the suggestion and its reason, alternative chips, and flags (unusual amount, new merchant, possible duplicate, possible reimbursement).
- Recategorize opens a picker, then the **scope chips** with the best guess pre-selected and "changes N past". Review by merchant (batch). Desktop keyboard shortcuts.
- Dwell time is measured client-side and sent with each label (weights and gamification depend on it). Never block on it.
- Playwright: `review-swipe.spec.ts`, `review-scope.spec.ts`, `review-batch.spec.ts`.

### [ ] M8.5 money flows (screens 3, 4, 5, 6, 7)
- **Uncategorized:** the amount and why (the decomposition from M4.6), allocation sliders or amounts, a one-time or permanent toggle with a consequence line from the M5.9 preview, and what happens at month end.
- **Cover sheet:** "you're over by $X. where should it come from?", with sources, consequences, splits and the suggested order.
- **Owed to you:** receivables, waiting-for-the-charge cards, counterparty cards, and the link picker.
- **Money:** envelopes, goals with projected dates, the EF percentage and rebuild plan, discretionary, sinking funds, and the rollover checklist.
- **Bills and subscriptions:** reuse the legacy subscriptions page (`web/src/Recurring.tsx`), backed by the new API, plus payment plans and "mark as recurring".

### [ ] M8.6 remaining screens (8 to 12)
- Accounts and data health (basic; M9 completes it), rules and learning (list, debugger, patterns, counterparties, accuracy), activity (search and detail with the decision history), insights (placeholder until M9), and settings (budget settings, notifications, privacy mode, security, export, tunable defaults).

### [ ] M8.7 onboarding wizard (screen 13, S19.7)
Resumable, skippable and re-runnable:
1. Connect (claim a token).
2. Classify accounts: kinds pre-filled by heuristics, and the **user confirms** (`known-facts.md`).
3. Coverage check with backfill progress.
4. Detected recurring items.
5. Savings, goals, EF and discretionary.
6. The teach-me queue (merchants by frequency times spend).
7. First plan reveal.
8. Notifications, with the iOS Home Screen install guide.

### [ ] M8.8 push and badging
- Reuse the VAPID code. Default pushes (S16, S19.3): auth failure, sync paused, overspend, projected shortfall, and the daily review reminder at a user-set time ("n need a look, m look fine"). **A weekly digest** goes out after 3 days away (S16), and prompts persist while the user is away.
- Quiet hours and at most 1 reminder a day. Badging API for the review count. iOS constraints copy.

### [ ] M8.9a should i buy this (S10)
- Keep the screen from the legacy app (`web/src/ShouldIBuy.tsx`) but drive it from the server: `GET /api/v1/home/can-afford?amount=` returns whether the purchase fits `spend_left` plus discretionary and, if it would overspend, **which source would be hit**. It informs only (S10) and writes nothing. The server computes it by running `ComputeMonth` on an in-memory copy (the M5.9 preview path), never in TypeScript.
- Tests: `TestS10_CanAffordNamesSourceHit`, `TestS10_CanAffordWritesNothing`.

### [ ] M8.9b platform UX (S19.20)
- Theme: dark, light and system from tokens. **Localization:** locale-aware currency and dates, week start, right-to-left layout, and a test that renders each screen in `rtl`.
- **Share target** for quick-add and receipt capture (web manifest `share_target`), home-screen shortcuts (manifest `shortcuts`: review, add transaction), and an optional **app lock** (PIN or device auth when the app returns from background).
- **Undo toasts everywhere** a decision is made (design brief principle 3), and skeleton loading for every list.
- Tests: Playwright `share-target.spec.ts`, `app-lock.spec.ts`, `rtl.spec.ts`.

### [ ] M8.9 accessibility and states
- WCAG 2.2 AA: axe in every Playwright spec, 44px targets (`docs/design-brief.md`), focus order, reduced motion (already respected by `motion.ts`), and no color-only information.
- Every screen has loading, empty, error, offline, stale, partial and privacy states (S19.19 privacy mode: amounts hidden until tapped).

### [ ] M8.10 legacy importer and cutover rehearsal
- Implement `internal/legacyimport` and `sofar import-legacy` per `docs/plan/legacy-migration.md`, with its tests.
- The owner provides a pg_dump of their deployed database. Restore it into a scratch database, run the dry run, review it **with the owner**, apply it to the scratch copy, and let the owner click through the app.
- **Gate:** the owner approves, then runs the cutover runbook (section 4 of `legacy-migration.md`). Merge `rebuild` into `main` only after the owner confirms the deployed result.
