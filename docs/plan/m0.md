**Goal:** the repo has the target layout, versioned migrations, config, redacted logging, a job queue, CI and Docker Compose. `docker compose up` shows a working login page. The legacy budget code is gone from this branch (it lives on in `main` and in git history).

**Exit criteria:**
- `docker compose up` gives a login page, and setup and login work.
- CI is green: `go vet`, `go test`, gofmt check, integration tests against Postgres, and the web build and tests.
- A test proves secrets never appear in logs.

### [ ] M0.7 auth upgrades (`internal/auth`)
Port setup, login, logout, TOTP enable and disable, password change, trusted-proxy client IP and failed-login slowdown, with their tests.
- **Sliding sessions** (S17): 30 days from last use. `last_seen_at` updates at most once an hour per session, to limit writes.

### [ ] M0.8 job queue and scheduler (`internal/jobs`)
- `Enqueue(ctx, tx *sql.Tx, kind, key string, runAt time.Time, payload any)` inserts with `ON CONFLICT (key) DO NOTHING`, inside the caller's transaction (A1: jobs are enqueued in the same transaction as the change).
- A worker loop picks due jobs with `FOR UPDATE SKIP LOCKED`, runs a registered handler, retries with backoff and records errors.
- Scheduler: a registry of periodic kinds, each with a function `NextKeys(lastDone, now, homeTZ) []Key` that returns missing keyed runs (catch-up, A7). A Postgres advisory lock means only one process schedules.
- Tests: `TestJobs_EnqueueIsIdempotentByKey`, `TestJobs_RollbackDropsEnqueuedJob`, `TestJobs_CatchUpEnqueuesMissedKeys`, `TestJobs_OnlyOneSchedulerHoldsLock`.
