# M6 categorization and rules engine

Spec: S1a, S11 (review, rules), S18a (all of it). Architecture: A5, A9.4, A9.10. Port ideas and data from `git show main:server/suggest.go` and `internal/normalize/merchants.json` (moved in M0).

**Goal:** normalization, a rules DSL with traces, the learning layers, calibrated arbitration, triage, the prequential evaluation recorder, and the review API.

**Exit criteria:**
- S18a edge cases 1 to 15 pass, and invariant 12 passes.
- The simulation harness reports teach-once and first-pass accuracy against the A9.10 gates.
- The rules debugger reproduces any decision.

---

### [x] M6.1 simulation harness (`internal/sim`)
A seeded synthetic-life generator (A9.4) that M6, M7, M9 and M12 all reuse. Build it first so the learning tasks can be measured as they land.
- Salary at any interval and irregular side income.
- Monthly and annual bills, and subscriptions with price hikes.
- Merchants with ambiguous categories (Amazon, Walmart, gas stations).
- P2P paybacks with realistic lag, and pending-then-posted card purchases with tip changes.
- Duplicate and rotated ids, missing days, and outages.
- A "user" oracle that labels with a configurable error rate.
- Output: raw provider batches plus ground-truth labels.
- Tests: `TestSim_DeterministicBySeed`.

### [x] M6.2 normalization and merchants (`internal/normalize`)
- Port `Prettify` and extend it per S18a:
  - strip processor prefixes (`SQ *`, `TST*`, `PAYPAL *`, `Master Money`, and the rest of the existing list), store numbers, POS and terminal codes, dates, phone numbers, card digits and trailing locations
  - keep the processor as a separate feature
- Merchant entities with aliases. Fuzzy alias clustering by character n-gram similarity **proposes** merges; the user merges or splits. Alias healing re-points rules when a descriptor drifts.
- Mark ambiguous multi-category merchants (seeded list plus learned).
- Bank strings are untrusted: cap the length, strip control characters, and never build regexes from them.
- Tests: `TestS18a_NormalizeStripsProcessorAndStoreNumbers` (use the shapes in `known-facts.md`), `TestS18a_AliasClusteringProposesNotApplies`, `TestS18a_E1_DescriptorRenameHeals`, plus a fuzz test for the normalizer.

### [x] M6.3 rules DSL and evaluator (`internal/rules`)
- JSON conditions: an AND, OR and NOT tree over the S18a fields with the operators is, contains, starts with, ends with, regex, one of, fuzzy at least N, and their negations. **Regex uses Go RE2 only**, with a length cap. Amount conditions: exact, between, at least, at most, within a percentage.
- Actions from S18a (category, tag, rename merchant, note, type, expecting reimbursement, link to a bill, from discretionary, month, hide, flag, skip learning, split).
- Layers (user, learned) and stages (pre, default, post). Within a layer: specificity, then priority, then recency. "Stop processing" is supported.
- `Evaluate(txn, rules) (Result, Trace)`. The trace lists every rule evaluated, why it matched or not, and which one won.
- Versioning (`rule_versions`) with rollback. Time-bound rules. Import and export as JSON, including **shareable seed rule packs** (a named bundle of rules that can be imported without overwriting user rules).
- Migrate the legacy pattern rules' shape (`legacy-migration.md` section 3).
- Tests: `TestS18a_UserRuleBeatsLearned`, `TestS18a_SpecificityOrder`, `TestS18a_StopProcessing`, `TestS18a_TraceExplainsEveryRule`, `TestS18a_RegexIsRE2AndBounded`, `TestS18a_RuleVersionRollback`, `TestS18a_TimeBoundRule`.

### [x] M6.4 rule tooling
- **Preview:** "matches N existing transactions", with the list. **Backtest:** a diff of what would change historically. **Apply to past:** one event, undoable (S18a "retroactive scope": reviewed transactions change only with this explicit action).
- The debugger endpoint takes any transaction id. Rule health: hits, accepted, corrected, precision, last hit, and detection of shadowed, overlapping, conflicting, stale (archived after 90 days without hits) and low-precision (auto-demoted) rules.
- Tests: `TestS18a_BacktestWritesNothing`, `TestS18a_ApplyToPastUndoable`, `TestS18a_ShadowedRuleDetected`, `TestS18a_E6_LowPrecisionAutoDemoted`.

### [x] M6.5 seed rules and starter prior
- Seed rules also cover S13 card interest (interest on a linked card is spending, category `fees_interest`) and S11 fees (bank and overdraft fees).
- Re-map `merchants.json` to the S1a category ids (mapping in `legacy-migration.md`) as **seed rules** (layer "seed", below user and learned) and a starter prior (keywords). The prior never trains on its own guesses and fades as personal labels accumulate (S18a).
- Tests: `TestS18a_SeedRulesUseStableIDs`, `TestS18a_E12_NewMerchantFallsBackToPrior`.

### [x] M6.6 labels and learned rules (`internal/learn`)
- `label_events` for every review: suggested, source, confidence, final, scope, weight (explicit pick 2, correction 3, quick confirm 1, reduced silently when under 1.5 seconds or in a rapid streak), session and time.
- **Scope prompt data:** propose the most likely generalization, with the count of past transactions it would change. Scopes: this time only (an **exception**, never trains), this merchant, this merchant in an amount range, this merchant on this account, this description pattern.
- **Induction:** 2 consistent labels make a merchant rule for a non-ambiguous merchant; 3 make a conditional rule with clean separation. Probation for the first 5 matches.
- **Ambiguity:** contradictory labels that are not separable create no rule and send the merchant to review with its top 2 or 3.
- **Drift:** older labels decay; 3 consecutive corrections against a learned rule prompt "update this rule?". **Conflict** with a user rule: the user rule wins and the engine asks (edit, exception, delete). **Undo learning** removes a label's influence without changing the transaction.
- Invariant 12: learning reads only label events with source `user` (or `legacy-import`, which is a real user decision).
- Tests: `TestS18a_TwoLabelsInduceMerchantRule`, `TestS18a_ThreeLabelsForConditionalRule`, `TestS18a_ProbationFiveMatches`, `TestS18a_E4_AmbiguousMerchantNoRule`, `TestS18a_E5_CorrectionVsUserRuleAsks`, `TestS18a_E7_DriftPrompt`, `TestS18a_E8_RubberStampWeightReduced`, `TestS18a_E9_OneOffIsException`, `TestS18a_E11_UndoLearning`, `TestA9_Inv12_LearnOnlyFromUserLabels`.

### [x] M6.7 statistical layers and arbitration
- **Features** (S18a list): character n-grams 2 to 5 and words over merchant, description, memo and payee; merchant id and processor; amount log, exact match and relation to merchant history; roundness; direction, account and account type; recurrence; calendar; context; P2P memo.
- **Case memory:** nearest neighbors over that feature vector, with explanations ("similar: chevron $48, 9 times, all fuel").
- **Logistic regression:** hashed features, class weights, online SGD, and refit in a background job after a batch of labels. Model snapshots are versioned in `model_snapshots`, with rollback.
- **Calibration:** Beta posteriors for rules; Platt (or isotonic) scaling for the model, refreshed from the evaluation log.
- **Arbitration:** one suggestion with calibrated confidence, a reason and up to 3 alternatives. Structural detectors (transfers, schedules, refunds and reimbursement candidates) run first and take precedence (S18a "special cases").
- **Triage order:** uncertain first, then unusual amounts, then new merchants, then routine items. Surprise flags for amount outliers at a consistent merchant.
- Suggestions stay live until confirmed. Re-evaluate unreviewed items when rules or the model change; reviewed items are never touched.
- Tests: `TestS18a_E13_AccountConditionedSplitsPersonalVsBusiness`, `TestS18a_E14_RecurringVsDiscretionarySameMerchant`, `TestS18a_SurpriseFlagOnOutlier`, `TestS18a_SuggestionLiveUntilConfirmed`, `TestS18a_ReviewedNeverReevaluated`.

### [x] M6.8 evaluation and self-checks
- Persist every suggestion **before** its label (prequential). A nightly `evaluate` job computes acceptance overall, by source and confidence bucket (the calibration curve), the confusion matrix, worst merchants and the trend.
- **Retro-review** ("possible past errors"): confirmed rows the engine now strongly disagrees with.
- **Audit mode** (off by default): hide the suggestion on a small random share of high-confidence items.
- **Gates** (A9.10) from the simulation: teach-once at least 95%, first-pass at least 90% by day 30 and at least 95% by day 90. Report them in CI as numbers, and fail the job if they fall below the gate on the standard seed set.
- Tests: `TestA9_10_TeachOnceGate`, `TestA9_10_FirstPassGates`, `TestS18a_RetroReviewFindsLabelNoise`, `TestS18a_AuditModeHidesSuggestion`.
