# M3 budget core (walking skeleton)

Spec: S0, S2, S3, S4 (plan, overrides), S10 (spend_left, per day), S17, S18 (learning phase). Architecture: A2, A9.2, A9.3. **Read `docs/plan/engine-semantics.md` in full before starting.**

**Goal:** `budget.ComputeMonth` per the engine semantics, recompute with early cutoff, plan overrides, the learning phase, explainability, and a hero number on screen.

**Exit criteria:**
- Worked examples A to D pass to the cent, month by month.
- Invariants 1, 2, 3, 4, 5, 6, 10 and 13 pass.
- Recompute from scratch equals incremental recompute.
- A sync or fixture produces a rendered safe-to-spend number.

Overspend, covers, goals, the EF and discretionary arrive in M5. Write their types now so M5 only adds behavior.

### [x] M3.4 recompute (`internal/recompute`)
- `month_snapshots` (migration `00004_snapshots.sql`): month, engine_version, input_hash, state jsonb, computed_at. `dirty_months` (month, reason, marked_at).
- `Assemble(ctx, q, month) MonthInputs`:
  - income for `I(M-1)`, following section 2 of engine-semantics (only what exists so far; schedules arrive in M4)
  - outflows net of links (links in M7; for now none)
  - lines (empty until M4 and M5)
  - events for the month
  - the learning flag from coverage
  - the plan override
- `Recompute(ctx, from YearMonth)` walks forward from the earliest dirty month. **Early cutoff:** stop when a recomputed state hash equals the stored snapshot and the next month's own inputs did not change. The current month always recomputes.
- Mark dirty on: a transaction change (its month and the next one, because of the plan), a link change, a config version, or a budget event. Marking happens in the same database transaction as the change (A1).
- CLI: `sofar recompute --all` and `sofar recompute --from 2026-09`.
- Tests: `TestA9_Inv5_RecomputeFromScratchEqualsIncremental` (rapid), `TestA9_Inv6_RecomputeTwiceSame`, `TestRecompute_EarlyCutoffStopsChain`, `TestS3_LateTransactionRecomputesItsMonthAndNext`.

### [x] M3.5 plan overrides, learning phase, partial months (S4, S18, S13)
- Event `plan.override` {month, cents, note}; undo removes it. The next month's delta uses the effective plan (S4).
- Learning (S18): if there is no complete prior calendar month for every budget account and no override, `Learning = true`, plan = 0 and the hero shows "learning". A manual starting plan at any time is a `plan.override`.
- Partial (S13): from coverage, label the plan "partial" and keep it overridable.
- Tests: `TestS4_OverrideUsedAndNoted`, `TestS18_LearningUntilCompletePriorMonth`, `TestS18_ManualStartingPlanEndsLearning`, `TestS13_PartialMonthLabeled`.
